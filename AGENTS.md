# Working on A2B as an AI agent (Codex and others)

This is how the owner (Thaqif, `@thaqif0709`) and his AI sessions work in this repository. Follow it as you would
`CLAUDE.md`, which says the same rules for Claude sessions. Contributors: see `CONTRIBUTING.md`.

A2B is a free, open-source Waze/TuJu-style navigation web app for Malaysia: a Cloudflare Worker (`src/worker.js`)
with a D1 database, serving plain JavaScript modules from `public/` (no build step). Live at
https://a2b-beta.pages.dev. The repo is public.

## How the owner likes to work

- Do what's asked, and don't start long reviews or big changes on your own. He's watching token use.
- Talk plainly: what changed, what you checked, what he needs to decide. No jargon without explaining it.
- Never merge or deploy unless he says so in that conversation ("merge", "deploy", "merge and deploy").
- When a decision is his (money, privacy, data sources, design), lay out the options with a recommendation and stop.

## Rules (never break these)

- **Never push to `main`.** One change per branch (`codex/<short-topic>`), one change per commit, a message that
  says what and why. Open a pull request against `main` that fills in `.github/pull_request_template.md`.
- **Never print, echo or commit secrets:** the Cloudflare API token, `TOMTOM_KEY`, `TESTER_EMAILS`, `OCM_KEY`, or
  anyone's email. Secrets live in Cloudflare (`npx wrangler secret put NAME`) or the git-ignored `.dev.vars`.
- **Keep it free to run.** Anything needing a paid plan or paid API is the owner's call first.
- **Privacy is a feature.** A2B keeps no trip history, sells nothing, has no ads. Don't send users' searches,
  positions or IPs to third parties unless the user taps something that clearly does so.
- **Respect public services** (Valhalla at `valhalla1.openstreetmap.de`, Photon, Overpass, OpenFreeMap): few
  requests, cached, no bulk use from drivers' requests.

## Before opening or merging any PR

Run these. Tests alone are not enough: `npm test` never loads `public/app.js` itself, so a broken app can pass.

```sh
npm test                                     # must end "fail 0"
node --check public/app.js                   # and any other changed public/*.js and src/*.js
git merge-tree --write-tree origin/main HEAD # merges cleanly with main?
```

For anything visual or on the road, try it in a browser against `npx wrangler dev --port 8787 --local`
(Playwright works; a fake GPS via `context.setGeolocation`). For tester-only screens, put
`TESTER_EMAILS=tester@example.com` in `.dev.vars` locally and delete the file afterwards. Each fresh browser
counts as a new guest: if you hit the 30-guest limit locally, run
`npx wrangler d1 execute a2b --local --command "DELETE FROM presence"`.

## Reviewing other people's PRs

Contributors so far: Adrian (`AdrianFu0329`, most PRs), aafham, alfirus, Edvin. Adrian and Edvin have repo access
and may merge; only the owner's Cloudflare account can deploy.

1. Fetch it: `git fetch origin pull/<n>/head:pr<n>`. Read the description and the diff.
2. Test it merged onto current main (not just on its branch):
   `git checkout --detach origin/main && git merge --no-edit pr<n> && npm test && node --check public/app.js`.
   Two PRs can each pass alone and break together (e.g. both declaring the same top-level `let` in `app.js`).
3. Check the CLA box is really ticked by the person (an AI-written "pending confirmation" note doesn't count).
4. Post the review signed exactly like this, ending with the footer:

   ```
   — **Thaqif's Claude** (AI reviewer for A2B)

   ---
   _Generated by [Claude Code](https://claude.ai/code)_
   ```
   (From Codex, sign "— **Thaqif's Codex** (AI reviewer for A2B)" and leave the footer out.)

5. "Request changes" blocks merging until an approving review replaces it, so approve before merging once fixed.
6. When PRs conflict only in `public/sw.js`'s `SHELL` list, the README, or side-by-side imports, keep both sides on
   a `codex/land-<n>-<m>` branch and open one PR; merging it marks the original PRs merged.

Things that have needed fixing before, worth checking every time:

- **Traffic data:** only real drives feed `noteProbeFix` (`mode === 'drive' && travel === 'drive' && !sim`).
  Walking, trains, tunnel-mode guesses and demo drives must never become traffic.
- **Auto-start:** only Drive routes count down and start by themselves (`canAutoStartRoute` in
  `public/route-preview.js`). Walk and Train always need a tap. Every trip starts on Drive.
- **Reports:** no road reports from a train trip (`canReportFrom` in `public/report-types.js`).
- **Data that expires:** train timetables (`src/lib/transit-data.json`, KTMB until 11 Nov 2026, Prasarana until
  31 Dec 2026) need `npm run transit` and a redeploy before then.
- **Google:** its Places API data may not be shown on a non-Google map or stored. A2B dropped the Google fallback.

## Deploying (only when the owner says so)

```sh
git checkout main && git pull
npx wrangler d1 migrations apply a2b --remote   # before deploying code that needs it; usually "No migrations"
npm test
npm run deploy                                  # predeploy prints "Place data: Overture …, N places"
```

- The predeploy step stops the deploy if the live database is missing a migration (`scripts/check-migrations.mjs`).
  Apply it, then deploy again. `SKIP_MIGRATION_CHECK=1` skips the check (only for rolling back code).

- `public/places/` (shop search) isn't in git. On a fresh checkout build it first:
  `pip install duckdb && npm run places`. Deploying without it removes shop search from the live app.
- After deploying, check the live site: fetch a changed file (add `?v=<timestamp>`; Cloudflare's cache can serve
  the old copy for a minute) and load https://a2b-beta.pages.dev once in a headless browser with no page errors.
- `public/sw.js` loads the app's own files network-first, so new code reaches phones straight away. Bump
  `const CACHE = 'a2b-vNN'` when the `SHELL` file list changes, so new files are kept for offline use.
- Rollback if needed: `npx wrangler rollback`, or Cloudflare dashboard › Workers & Pages › a2b › Deployments.
